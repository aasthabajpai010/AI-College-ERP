## Collections

### User

Stores login credentials and role for every person in the system — Admin, Faculty, and Student accounts all live in this one collection, differentiated by `role`.

| Field | Type | Constraints | Notes |
|---|---|---|---|
| `_id` | ObjectId | Primary Key | Auto-generated by MongoDB |
| `name` | String | Required | |
| `email` | String | Required, Unique | Indexed automatically via `unique: true` |
| `password` | String | Required | Bcrypt hash, never stored or returned in plain text |
| `role` | String | Required, enum | One of `admin`, `faculty`, `student`; defaults to `student` |
| `createdAt` | Date | Auto | Mongoose timestamp |
| `updatedAt` | Date | Auto | Mongoose timestamp |

### Student

The academic profile linked to a login account. Separated from `User` because not every User is a Student (Admins and Faculty are Users too, without a Student profile).

| Field | Type | Constraints | Notes |
|---|---|---|---|

| `user` | ObjectId | **Foreign Key** → `User._id`, Required | 1:1 — one Student profile per User account |
| `department` | ObjectId | **Foreign Key** → `Department._id`, Required | |
| `rollNumber` | String | Required, Unique | |
| `semester` | Number | Required | 1–8 |
| `section` | String | Required | |
| `phone` | String | Optional | |
| `address` | String | Optional | |
| `createdAt` | Date | Auto | |
| `updatedAt` | Date | Auto | |

**Indexes:**
- `{ department: 1 }` — single-field index, speeds up "all students in department X" queries
- `{ department: 1, semester: 1 }` — compound index, speeds up "all students in department X, semester Y"

### Attendance

One document per student, per date.

| Field | Type | Constraints | Notes |
|---|---|---|---|
| `_id` | ObjectId | Primary Key | |
| `student` | ObjectId | **Foreign Key** → `Student._id`, Required | |
| `date` | Date | Required | |
| `status` | String | Required, enum | `present` or `absent` |
| `markedBy` | ObjectId | **Foreign Key** → `User._id`, Required | Audit trail — which Faculty/Admin marked this record |
| `createdAt` | Date | Auto | |
| `updatedAt` | Date | Auto | |

**Indexes:**
- `{ student: 1, date: 1 }` — **compound unique index**. Guarantees at the database level that a student cannot have two attendance records for the same date, even under concurrent requests.

## Relationships Summary

| Relationship | Type | Description |
|---|---|---|
| User → Student | 1 : 1 | Each Student profile references exactly one User account |
| Department → Student | 1 : N | One department has many students |
| Student → Attendance | 1 : N | One student has many attendance records |
| Student → Result | 1 : N | One student has many result records |
| User → Attendance (markedBy) | 1 : N | Audit trail — one Faculty/Admin marks many attendance records |
| User → Result (enteredBy) | 1 : N | Audit trail — one Faculty/Admin enters many results |
| User → Notice (postedBy) | 1 : N | One Faculty/Admin posts many notices |
| Department → Notice | 1 : N (optional) | A notice may optionally target one department |

---

## Why References Instead of Embedding

Mongoose supports both embedding sub-documents directly and referencing separate documents (via `ObjectId` + `populate()`). This project uses **references** for all the relationships above, deliberately:

- **Department** is shared across many Students and updated independently of any single student. A reference means updating a department's name once reflects everywhere via `populate()`, instead of needing to update it on every Student document that embedded a copy.
- **User ↔ Student** separation keeps authentication concerns (login, password, role) independent from academic profile data — an Admin or Faculty account never needs Student-shaped fields at all.

The trade-off is an extra `populate()` call at query time (equivalent to a SQL JOIN) versus the single-document read embedding would allow — an acceptable cost at this project's scale, and the standard practice for genuinely shared, independently-updated reference data.
